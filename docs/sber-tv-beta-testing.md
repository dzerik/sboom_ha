# Проверка беты на Sber TV

Для отчёта нужны модель телевизора, версия его ПО и версия беты SBoom. Шаг 1 выполняется из Home Assistant. Для шагов 2 и 3 понадобится компьютер в той же локальной сети и физический доступ к телевизору. Держите пульт рядом, чтобы восстановить исходный вход или включить ТВ после проверки ожидания.

## Шаг 1. Проверить пять действий в Home Assistant

Включите уже сопряжённый телевизор. Откройте **Настройки → Устройства и службы → SBoom**. В настройках записи телевизора включите **Экспериментальные функции ТВ**. В **Инструменты разработчика → Действия** выберите `sboom_ha.tv_action` и один телевизор. Вызывайте команды по одной.

| Команда | Как подготовиться и что записать |
| --- | --- |
| `show_inputs` | Закройте меню. Проверьте, появился ли список входов. |
| `next_input` | Запишите текущий вход, отправьте команду, затем сверьте подпись выбранного входа на экране. |
| `channel_up` | Откройте эфирное ТВ с настроенными каналами. Запишите номер канала до и после вызова. |
| `channel_down` | В эфирном ТВ снова запишите номер канала до и после вызова. |
| `settings` | Закройте меню настроек. После команды посмотрите, открылись ли настройки. |

Для каждой строки запишите ответ и **что изменилось на экране**. Успешно завершившийся вызов HA означает, что ТВ прислал `OK` в ответе на директиву. Если изображение осталось прежним, запишите **«OK без эффекта»**. При ошибке сообщите её категорию, например «таймаут» или «нет подтверждения». Проверьте экран перед ручным повтором.

## Шаг 2. Проверить физический вход HDMI1

Переходите к этому шагу, если `show_inputs` открыл список входов и у телевизора есть разъём HDMI1. Подключите к HDMI1 включённый источник с узнаваемым изображением и выберите на ТВ другой вход.

Скачайте **Source code (zip)** со страницы установленного бета-релиза и распакуйте. Также подойдёт git-копия на теге этого же релиза. Откройте терминал в корне исходников, где лежат `requirements-test.txt` и каталог `research`. На Linux/macOS с Python 3.12 выполните команды ниже. Вместо `192.0.2.10` укажите адрес своего ТВ из его сетевых настроек.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python research/tv_beta_check.py 192.0.2.10
```

На Windows в PowerShell команды выглядят так.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe research\tv_beta_check.py 192.0.2.10
```

При приглашении утилиты нажмите `+` на ТВ для отдельного сопряжения. Если ТВ предлагает только экранный PIN, завершите проверку и укажите это в отчёте. Утилита использует токен только в памяти до выхода.

Введите `hdmi1` и нажмите Enter. Запишите результат поля 4, подпись выбранного входа и появилось ли изображение с подключённого устройства. Если открылся лишь список входов, отметьте именно это. Завершите сеанс командой `q`.

## Шаг 3. Проверить питание и новое подключение в ожидании

Включите экран, снова запустите утилиту и выполните сопряжение. Оставьте этот экземпляр запущенным до конца всех проверок питания.

1. На включённом ТВ введите `off`. Запишите результат поля 6 и числовой код, если он показан. Отметьте, что стало с панелью, звуком и индикатором питания. При таймауте команда могла успеть погасить экран.
2. Когда ТВ визуально перейдёт в ожидание, введите `mark`. Утилита начнёт отсчёт с этой отметки. После короткой паузы, например 10 секунд, введите `on` на текущем соединении. Запишите время, ответ, появление изображения и звука.
3. Для отдельного опыта верните ТВ в известное включённое состояние пультом. Переведите его пультом в ожидание, отметьте `mark` и выждите выбранный интервал. Введите `reconnect`. Эта команда открывает новое WSS-соединение без повторного сопряжения. Запишите, открылось ли оно. При успехе вручную введите `on` и запишите поле 6 и реакцию телевизора. При отказе соединения запишите «WSS недоступен, ON не отправлен».
4. Повторите предыдущий опыт после более длительного ожидания, например через 5 минут, а при наличии на модели глубокого сна — после перехода в него. Укажите фактическое время и наблюдавшиеся признаки режима. Если ТВ остался выключенным, включите его пультом и выберите `reconnect` для восстановления соединения. Завершите сеанс командой `q`.

Утилита проверяет минимальный вариант `tv_power` со строкой JSON `{"type":"ON"}` или `{"type":"OFF"}`. Поле `base_command` в этом варианте опущено. Если ТВ отклоняет команду, запишите ответ. Необходимость этого поля для конкретной прошивки остаётся открытым вопросом. Поддержка питания и прямого выбора HDMI в HA зависит от результатов таких проверок.

## Что прислать

Откройте задачу в репозитории и вставьте в неё шаблон ниже. Добавьте по одной строке на каждое проверенное действие. [Отправить отчёт о Sber TV](https://github.com/dzerik/sboom_ha/issues/new)

Включайте только наблюдения, без IP, MAC, серийного номера, идентификаторов HA и токенов. Сетевые журналы и полные снимки экрана для отчёта не нужны.

```text
Модель ТВ и версия ПО:
Версия Home Assistant и версия беты SBoom:
Команда | исходное состояние | ответ HA или поле 4/6 | наблюдаемый результат
show_inputs | приложение каналов | OK | открыт список входов
...
Питание | исходное состояние | время с mark | текущее/новое WSS и результат подключения | ответ ON/OFF | панель, звук, индикатор
...
```
