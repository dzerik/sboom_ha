# Улучшения панели и каталога SBoom

Пользователь одобрил предложение из `research/SBOOM_NODE_COMPARISON.md`:
сначала Bluetooth-панель, история успешных запусков и устойчивость каталога.
Мультирум остаётся отдельным этапом с аппаратной проверкой точности.

## Результат для пользователя

- В существующей панели есть раздел Bluetooth: сопряжение, обновление списка
  спаренных, поиск устройств поблизости и connect/disconnect/remove по MAC.
  Это команды колонки через существующий WSS; отдельный BT-адаптер не нужен.
  Нет фиктивного тумблера питания или подтверждённого таймера видимости.
- В браузере каталога доступны недавние и частые успешные запуски, повторное
  воспроизведение и очистка. История сохраняется в HA Store, отдельно по
  пользователям, максимум 100 элементов на пользователя. Запись после принятия
  команды колонкой, один раз на пользовательский запуск. Неудачи не учитываются.
- Поиск каталога переживает временные HTTP/сетевые ошибки: ограниченный retry,
  REST и GraphQL fallback/merge, ограниченный кеш с возвратом последнего
  успешного результата при сбое. Ошибки не кешируются как найденное отсутствие.

## Архитектура и ограничения

Python 3.11+, HA 2024.12+, существующие зависимости. Один WS на coordinator.
HA WebSocket API для панели, Lit-компоненты на существующих токенах темы.
Никакого отдельного HTTP-сервера и никаких новых облачных токенов пользователя.
Интервалы volume poll и существующие команды не меняются.

`api.get_scanned_bt_devices()` формирует op21 с пустым вложенным field1 и
передаёт ответ существующему parse_scanned_bt. Для scan timeout 15 секунд.
Сериализация BT-операций не позволяет параллельным scan и управлению устройством
портить снимок; отмена/ошибка освобождает блокировку. Список после команды
перечитывается и не подменяется предполагаемым подтверждением.

`play_history.py` владеет загрузкой, валидацией, ограничением размера и записью
истории. Общий helper используется WS play и play_music. История пользователя
доступна только этому пользователю; очистка не затрагивает других.
Ошибка хранения не превращает уже успешное воспроизведение в ошибку команды.

Каталог сохраняет публичный формат search `{best,artists,releases,tracks,playlists}`.
Кеш: LRU до 64 запросов, свежий результат до 60 секунд; старый результат можно
вернуть при временном отказе не позднее 15 минут после успеха. Возврат копии
защищает кеш от мутаций потребителей. Retry ограничен тремя попытками, 429 и
502/503/504/сетевые ошибки; 401 обновляет анонимный токен единожды.
Нет повторов команд воспроизведения. Persistence cookies не добавляется в этом
этапе: для устойчивости используются текущий cookie jar и обновление токена.

## Проверка

Тесты сначала воспроизводят отсутствие новых возможностей. Проверяются op21,
таймаут/конкурентность BT, валидация MAC и действий, ошибочный/offline entry,
изоляция и персистентность истории, отказ storage, отклонённое воспроизведение,
fallback поиска, retry, истечение/ограничение кеша и неизменность ответа search.
Полный Python suite, py_compile, проверка JS и проверка интерфейса с mock HA.
Без команд реальным колонкам в рамках разработки.
